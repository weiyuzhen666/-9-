## S1：加权 RRF 融合（rrf_fusion）

### 实现

- 融合 5 路真实召回：`popular / content / itemcf / als / cold_start`，每路取 Top-20
- **严格按名次融合**：`score(d) = Σ w_r / (20 + rank_r(d))`，不跨量纲混加原始分数
- 去重、排序后输出 Top-10，每项带 `recall_sources` + `recall_ranks` 实现来源追溯
- 单路失败自动跳过，融合保持可用
- 权重：popular 0.6 / cold_start 0.63 / content 0.52 / itemcf 0.48 / als 0.22（由 validation P@10 比值平方根缩放并调平，避免热门垄断）

### 验收证据

| 场景 | 结果 |
|---|---|
| 正常请求（ml:14） | `status=ready`，`model_version=rrf-v1`，返回 10 条；#1 为 content+cold_start 双路共识片 |
| 来源追溯 | 每条结果显示 `召回来源 content#3 + cold_start#1` 样式，前端可见 |
| 异常请求（不存在用户 99999999） | `404 HISTORY_USER_NOT_FOUND`，无静默伪造 |
| 契约自检（evaluation 模式） | 6 算法全部 `validated_provider_output` |
| 前端交互 | 算法下拉新增"扩展算法 · 加权RRF融合"分组，控制台无 JS 错误 |

**浏览器截图**：`llm-assistant-screenshot.png` 同页可见 rrf_fusion 结果及来源标注。

## S2：LLM 工具调用

### 实现

- 端点：`GET /api/v1/assistant/query?q=...`（只读，无需 CSRF）
- **两个真实工具**：
  - `search_movies` — 对 MySQL `movies` 表做 SQL 检索（片名/类型）
  - `recommend_movies` — 调用 PROVIDERS 注册表里的推荐算法（默认 rrf_fusion）
- **双通道意图解析**：
  - 配置 LLM key 时走 **OpenAI 兼容 Function Calling**（当前使用智谱 GLM-4-Flash 免费模型）
  - 无 key 或 LLM 故障时自动降级为**预置解析**（手册允许的课堂方案）
  - 两条通道执行同一套真实工具
- 响应带 `generated_by: "由真实工具调用生成"` 标注 + 完整工具调用轨迹（名称/参数/结果）

### 验收证据

| 场景 | parser | 结果 |
|---|---|---|
| "推荐几部科幻片" | **llm** | 调用 `recommend_movies`（rrf_fusion，5 条） |
| "推荐几部科幻片"（无 key 时） | preset | 同时调用 `recommend_movies` + `search_movies`（Sci-Fi：Powder、12 Monkeys 等） |
| "Forrest Gump" | preset | 调用 `search_movies`，命中 Forrest Gump (1994) |
| 空查询 | — | `400 EMPTY_QUERY` |
| LLM 调用失败（余额不足等） | — | 自动降级 preset，日志记录 `LLM planning failed, falling back to preset parser` |

**浏览器截图**：`llm-assistant-result.png` 显示 parser=llm、"由真实工具调用生成"标注、工具调用轨迹。

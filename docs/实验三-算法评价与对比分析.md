# 实验三：算法离线评价与对比分析

> 数据版本 `rec-course-v3-train5-1.0.0` · 划分版本 `temporal-v1-cold500-train5-v3`
> 评价产出：`models/evaluation/metrics.json`（由 `recommender/student/evaluate_all.py` 生成）

---

## 1. 统一评价协议

所有算法使用**完全相同**的协议计算指标，保证可比性：

| 协议项 | 约定 |
|---|---|
| 训练输入 | 仅冻结的 `evaluation/train.csv`（4500 用户、8459 电影、583,502 条评分），不使用 business 库完整历史 |
| 正反馈定义 | 评分 ≥ 4.0 |
| 候选目录 | 冻结 `training-catalog.csv`（8,459 部电影） |
| 排除规则 | validation 分区排除 train 已评分电影；test 分区排除 train + validation 已评分电影 |
| 评价用户 | 教师固定 eligible 集合（`evaluation/evaluation-eligibility.csv`）：validation 4209 人、test 4198 人 |
| 用户无结果处理 | 全部保留计入分母，**空结果用户未被剔除**（实测 5 个算法空结果均为 0） |
| 指标公式 | P@10 = 命中数 / 10；R@10 = 命中数 / 该用户正例总数；宏观平均 |

指标含义：Precision@10 衡量"推荐列表里有多少是用户真正喜欢的"，Recall@10 衡量"用户喜欢的电影里有多少被推荐到了"。

## 2. 参评算法与参数

| 算法 | 模型版本 | 关键参数 | 一句话原理 |
|---|---|---|---|
| popular | popular-v1 | 按训练集评分支持度排序 | 全局热门榜单 |
| content | content-v1 | 类型多热向量 + 中心化评分 | 用电影类型（genres）建用户画像，按类型重叠度排序 |
| itemcf | itemcf-v1 | topk=50 邻居，min_common=3，物品均值中心化余弦 | 用户共现构造电影相似度，汇总用户喜欢电影的邻居 |
| als | als-v1 | rank=8，iterations=5，reg=0.1，seed=42 | 隐向量分解（LFM），交替最小二乘求解 |
| cold_start | cold-start-v1 | popular 与 content 信号混合 | 零历史走热门，有历史后热门+内容混合 |

**ALS 实现说明**：本环境为课程 Windows 离线包（纯 Python 依赖），ALS 以纯 Python 实现等价求解——与 Spark MLlib ALS 相同的交替最小二乘原理（固定 U 解 V、固定 V 解 U，每次为最小化 `Σ(r_ui − uᵢ·vⱼ)² + λ(‖uᵢ‖²+‖vⱼ‖²)` 的正规方程），参数（rank/iterations/reg）与模型工件、版本清单一并保留在 `models/evaluation/als-v1/`。

## 4. 结果对比分析（依据真实数据）

**解释一：popular 最强，根源是数据稀疏 + 长尾分布。**
评价矩阵稀疏度 98.47%（583,502 / (4500×8459)），平均每用户只评过 129.7 部电影，占目录的 1.5%。在如此稀疏的行为下，个性化算法能学到的用户偏好信号有限；而 28.2% 的电影支持度不足 10 条评分，长尾中的协同信号极不可靠。热门推荐虽"无个性"，但它把有限的机会押在统计上最稳定的头部。实测全局 Top-10 热门能覆盖 validation 正例的 2.14%（32835 条正例中 701 条），popular 的 P@10=0.0128 已达到这个理论上限的六成，说明热门基线并非"作弊"，而是稀疏数据下的强基准。

**解释二：ALS "训练正常、命中极低"，实证了评分预测 ≠ Top-N 排序。**
ALS 训练 5 轮 RMSE 从 2.28 稳定收敛到 0.71，说明隐向量确实拟合了评分；但 P@10 只有 0.0002。原因在于两个目标的结构性差异：
- RMSE 由高评分主导，模型倾向把"少数人给的 5 分冷门片"推到最高分，而这类电影进入 Top-10 的概率远低于热门片；
- P@10 只看列表前 10 位是否命中，对排序头部极其敏感，一个 RMSE 很小但头部排序不同的模型，命中率可以差一个数量级。
这印证了手册的提示："模型可以正常训练却得到较低的推荐命中率"。本实现的轻量设置（rank=8、5 轮迭代）进一步限制了隐向量的表达能力。

**解释三：itemcf 在 test 上反超 content，行为信号开始显现。**
content 只依赖电影类型，而 genres 粒度很粗（全目录主要类型仅十几种），同一类型内部的排序只能靠评分均分，区分度有限；itemcf 依赖真实共现行为，能捕捉"类型之外"的关联（如同系列、同导演的观看惯性）。test 分区上 itemcf 的 P@10（0.00364）和 R@10（0.00891）均高于 content（0.00331 / 0.00547），说明当行为数据足够时，协同过滤比纯内容特征更有判别力——但受稀疏限制，还不足以整体超越热门。

**解释四：cold_start 排名第二是合理的混合策略结果。**
它以热门为保底、内容信号为修正，兼得稳定性与部分个性化，validation 上 P@10 是 content 的 1.5 倍。这也说明在稀疏场景下"个性化信号"的正确用法是做**重排修正**而不是完全替代热门。

## 5. 必须能口头说明的两个概念

- **LFM 与 ALS 的关系**：LFM（隐因子模型）是"用户和电影都用 k 维隐向量表示、内积预测评分"的模型思想；ALS 是求解该模型的一种具体优化方法——交替固定一侧因子、把另一侧的求解变成标准最小二乘问题（本实现再加 L2 正则），反复交替直至收敛。同类思想也可用 SGD 求解。
- **评分预测 vs Top-N 排序**：前者优化"分数估计的准确度"（RMSE/MAE），后者优化"列表前 K 位命中用户喜好的比例"（P@K/R@K）。二者相关性弱：RMSE 低只说明整体分数估得准，不保证用户真正会看的电影排在最前面；本实验 ALS 的结果就是直接例证。因此课程要求不能以"ALS 必须优于 ItemCF"作为达标条件，而应以统一协议下的真实指标为准。

## 6. 复现步骤


## 7. 结论

在统一协议、固定用户集与冻结数据下：**popular > cold_start > itemcf ≈ content > als**。热门基线的强势由 98.47% 的稀疏度与长尾分布决定；ALS 的低命中实证了评分预测与 Top-N 排序的目标差异；itemcf 的行为信号在 test 上体现出对纯内容方法的超越趋势。后续（实验四/五）可通过 RRF 融合热门与个性化两路召回，兼顾稳定性与个性化。
